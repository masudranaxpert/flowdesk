# Generics ও Type Erasure

Java 5 এর পূর্বে কালেকশনগুলোতে যেকোনো object (`Object`) রাখা যেত। এর ফলে ডেভেলপারকে রিড করার সময় প্রতিবার ম্যানুয়াল কাস্টিং করতে হতো (যেমন: `String s = (String) list.get(0);`), এবং সামান্য ভুলে runtime-এ ভয়াবহ `ClassCastException` ক্র্যাশ ঘটত।

**Generics** হলো compile-time টাইপ সেফটি নিশ্চিত করার একটি ব্যবস্থা, যা কোডকে যেকোনো data type-এর জন্য পুনঃব্যবহারযোগ্য (Reusable) ও নিরাপদ করে তোলে।

---

## ১. Generic Class ও Method

একটি জেনেরিক class-এর সাধারণ রূপ:

```java
// Generic class with type parameter T
public class Box<T> {
    private T item;

    public void set(T item) {
        this.item = item;
    }

    public T get() {
        return this.item;
    }
}
```

```java
public class GenericsDemo {
    public static void main(String[] args) {
        // Type safe: compiler strictly enforces String type
        Box<String> stringBox = new Box<>();
        stringBox.set("Java 21");
        
        // No casting needed! Compile-time safe
        String val = stringBox.get();

        // stringBox.set(123); // COMPILATION ERROR! Prevents bug before running
    }

    // Generic Method
    public static <T> void printArray(T[] array) {
        for (T element : array) {
            System.out.print(element + " ");
        }
        System.out.println();
    }
}
```

## ২. বাউন্ডেড টাইপ parameter (Bounded Type Parameters)

যদি তুমি চাও যে জেনেরিক parameter-টি যেকোনো টাইপ না হয়ে শুধুমাত্র কোনো নির্দিষ্ট class-এর চাইল্ড বা interface ইমপ্লিমেন্টকারী হতে হবে:

```java
// T must be Number or a subclass of Number (Integer, Double, etc.)
public class NumericCalculator<T extends Number> {
    private T value;

    public NumericCalculator(T value) {
        this.value = value;
    }

    public double square() {
        // Can safely call doubleValue() because of the bound
        return value.doubleValue() * value.doubleValue();
    }
}
```

## ৩. ওয়াইল্ডকার্ড (Wildcards) এবং PECS নিয়ম

জেনেরিক্সে সবচেয়ে বিভ্রান্তিকর বিষয় হলো: `Integer` যদিও `Number` এর সাব-class, কিন্তু `List<Integer>` কখনোই `List<Number>` এর সাব-class নয়! একে ইনভ্যারিয়েন্স (Invariance) বলে।

এই সমস্যা সমাধানের জন্য এসেছে ওয়াইল্ডকার্ড (`?`):

1. **আনবাউন্ডেড ওয়াইল্ডকার্ড (`List<?>`)**: যেকোনো টাইপের লিস্ট (শুধু রিড করা যায়)।
2. **আপার বাউন্ডেড ওয়াইল্ডকার্ড (`List<? extends T>`)**: `T` বা তার যেকোনো সাব-টাইপ।
3. **লোয়ার বাউন্ডেড ওয়াইল্ডকার্ড (`List<? super T>`)**: `T` বা তার যেকোনো সুপার-টাইপ।

### PECS প্রিন্সিপল (Producer Extends, Consumer Super):
Effective Java-র বিখ্যাত গাইডলাইন (PECS):
- **Producer Extends**: যদি তোমার কালেকশনটি ডেটা উৎপাদন বা সরবরাহ করে (তুমি শুধু ডেটা পড়বে), তবে `<? extends T>` ব্যবহার করো।
- **Consumer Super**: যদি তোমার কালেকশনটি ডেটা গ্রহণ বা কনজিউম করে (তুমি কালেকশনে ডেটা লিখবে বা যোগ করবে), তবে `<? super T>` ব্যবহার করো।

```java
import java.util.List;

public class PecsDemo {
    // Producer: We ONLY READ numbers from the list
    public static double sumOfList(List<? extends Number> list) {
        double sum = 0.0;
        for (Number n : list) {
            sum += n.doubleValue();
        }
        // list.add(10); // COMPILATION ERROR! Cannot write to an 'extends' wildcard
        return sum;
    }

    // Consumer: We WRITE integers into the list
    public static void addNumbers(List<? super Integer> list) {
        for (int i = 1; i <= 5; i++) {
            list.add(i); // Safe to add Integer
        }
    }
}
```

## ৪. টাইপ ইরেজার (Type Erasure) — পর্দার পেছনের সত্য

অনেকেই মনে করেন সি++ এর টেমপ্লেটের মতো Java-তেও প্রতিটা জেনেরিক টাইপের জন্য আলাদা আলাদা মেশিন কোড তৈরি হয়। এটি ভুল!

Java পুরনো সংস্করণের সাথে ব্যাকওয়ার্ড কম্প্যাটিবিলিটি বজায় রাখতে **Type Erasure** ব্যবহার করে:
1. কোড কম্পাইল হওয়ার সময় compiler সমস্ত টাইপ চেকিং শেষ করে।
2. কম্পাইলেশন শেষে bytecode তৈরি করার সময় সমস্ত জেনেরিক টাইপ এনোটেশন (`<T>`, `<String>`) memory থেকে মুছে (Erase) ফেলা হয় এবং তাদের জায়গায় `Object` (অথবা বাউন্ডেড টাইপের ক্ষেত্রে বাউন্ড class-টি) বসিয়ে দেওয়া হয়।
3. যেখানে ভ্যালু রিড হয় সেখানে compiler প্রয়োজনীয় কাস্টিং bytecode ইনজেক্ট করে।

```java
// Your source code
List<String> list = new ArrayList<>();
list.add("Hello");
String s = list.get(0);

// Bytecode generated by compiler (conceptually)
List list = new ArrayList();
list.add("Hello");
String s = (String) list.get(0);
```

### টাইপ ইরেজারের কারণে সৃষ্ট সীমাবদ্ধতাসমূহ:
1. **primitive type ব্যবহার অসম্ভব**: `List<int>` লেখা যায় না, র্যাপার class `List<Integer>` ব্যবহার করতে হয়।
2. **runtime-এ জেনেরিক ইনস্ট্যান্স তৈরি নিষিদ্ধ**: `new T()` বা `new T[10]` লেখা যায় না।
3. **জেনেরিক্সে `instanceof` পরীক্ষা অবৈধ**: `if (list instanceof List<String>)` লেখা নিষিদ্ধ, কারণ runtime-এ এটি শুধুই একটি সাধারণ `List`।

## সারসংক্ষেপ

- জেনেরিক্স compile-time টাইপ সেফটি দেয় এবং অপ্রয়োজনীয় কাস্টিং ও `ClassCastException` দূর করে।
- ইনভ্যারিয়েন্স দূর করতে ওয়াইল্ডকার্ড ব্যবহৃত হয়; ডেটা পড়তে `extends` এবং লিখতে `super` (PECS)।
- টাইপ ইরেজারের কারণে bytecode-এ জেনেরিক টাইপ থাকে না, সব মুছে `Object` এ রূপান্তরিত হয়।
- পরবর্তী অধ্যায়ে আমরা শিখব Exception Handling — Checked, Unchecked ও Try-With-Resources।
