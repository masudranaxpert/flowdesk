# Sorting & Greedy Strategy (Preliminary Core)

গ্রিডি অ্যালগরিদম (Greedy Strategy) মানে হলো—"এই মুহূর্তে যেটা সবচেয়ে ভালো মনে হচ্ছে, সেটাই করো।" কনটেস্টে অনেক প্রবলেম থাকে যেগুলো দেখে অনেক কঠিন মনে হতে পারে, কিন্তু সর্টিং (Sorting) এবং একটু চালাকি করে খুব সহজেই $O(N \log N)$ এ সলভ করে ফেলা যায়।

## 🟢 পর্ব ১: বেসিক কনসেপ্ট (The Core Theory)

### ১. Greedy Approach কী?
ধরো তোমাকে বলা হলো, তোমার কাছে কিছু ১ টাকা, ২ টাকা, ৫ টাকা এবং ১০ টাকার কয়েন আছে। তোমাকে ৩৮ টাকা বানাতে হবে। তুমি কীভাবে সবচেয়ে কম সংখ্যক কয়েন দিয়ে বানাবে?
**গ্রিডি উপায়:** তুমি আগে সবচেয়ে বড় কয়েন (১০ টাকা) নেবে। ৩টা ১০ টাকার কয়েন নিলে ৩০ টাকা। তারপর ১টা ৫ টাকা, তারপর ১টা ২ টাকা, আর শেষে ১টা ১ টাকা। 
এটাই গ্রিডি! "সবচেয়ে বড় লাভ আগে তুলে নাও।"

### ২. K-Negation (Array Sum Maximization)
এটি গ্রিডির একদম ক্ল্যাসিক একটি প্রবলেম! 
**প্রবলেম:** তোমাকে একটি অ্যারে দেওয়া আছে এবং একটি সংখ্যা $K$ দেওয়া আছে। তুমি অ্যারের যেকোনো উপাদানের চিহ্ন (Sign) বদলাতে পারবে (অর্থাৎ $x$ কে $-x$ বা $-x$ কে $x$ করতে পারবে) সর্বোচ্চ $K$ বার। অ্যারের যোগফল সর্বোচ্চ কত করা যায়?

**ভিজ্যুয়ালাইজেশন (Thought Process):**
ধরো অ্যারে `A = [-5, -2, 3, 4]`, $K = 2$।
১. আমার টার্গেট হলো যোগফল বড় করা। তাই আমি চাইব ঋণাত্মক (Negative) সংখ্যাগুলোকে পজিটিভ বানিয়ে দিতে।
২. সবচেয়ে বড় ঋণাত্মক সংখ্যাকে (যার পরম মান বা Absolute value বড়) আগে পজিটিভ করলে লাভ সবচেয়ে বেশি! 
৩. তাই প্রথমে অ্যারেকে ছোট থেকে বড় আকারে সাজাব (Sort)। 
৪. এরপর প্রথম থেকে নেগেটিভ সংখ্যাগুলোকে পজিটিভ করতে থাকব, যতক্ষণ $K$ আছে।
৫. যদি নেগেটিভ সংখ্যা শেষ হয়ে যায় কিন্তু $K$ এখনো বাকি থাকে, তখন কী করব? 
   - যদি $K$ জোড় (Even) হয়, তবে কোনো সমস্যা নেই! (একই সংখ্যাকে দুইবার উল্টালে আগেরটাই থাকে)।
   - যদি $K$ বিজোড় (Odd) হয়, তবে আমাকে বাধ্য হয়ে কোনো একটা পজিটিভ সংখ্যাকে নেগেটিভ করতে হবে। সেক্ষেত্রে আমি অ্যারের সবচেয়ে ছোট পজিটিভ সংখ্যাটাকে নেগেটিভ করব, যাতে লস সবচেয়ে কম হয়!

**স্ট্যান্ডার্ড কোড:**
```cpp
#include <iostream>
#include <vector>
#include <algorithm>
using namespace std;

void maximize_k_negation() {
    int n, k;
    cin >> n >> k;
    vector<int> a(n);
    for (int i = 0; i < n; i++) cin >> a[i];

    // ১. ছোট থেকে বড় সাজানো
    sort(a.begin(), a.end());

    // ২. নেগেটিভ সংখ্যাগুলোকে পজিটিভ করা
    for (int i = 0; i < n; i++) {
        if (a[i] < 0 && k > 0) {
            a[i] = -a[i];
            k--;
        }
    }

    // ৩. যদি K বাকি থাকে এবং বিজোড় হয়, তবে সবচেয়ে ছোট সংখ্যাকে নেগেটিভ করা
    if (k % 2 != 0) {
        sort(a.begin(), a.end()); // পজিটিভ করার পর আবার সর্ট করে ছোটটা বের করি
        a[0] = -a[0];
    }

    // ৪. যোগফল বের করা
    long long sum = 0;
    for (int x : a) sum += x;
    cout << sum << "\n";
}
```

### 🍕 প্রবলেম ১: Selling Hot Pizzas (DIU Spring-26 Prelim A)
**প্রবলেম:** তোমার কাছে $N$ টি পিজ্জা আছে। প্রতি ১ মিনিটে তুমি ১টি পিজ্জা বিক্রি করতে পারবে এবং অবিক্রীত পিজ্জার দাম ১ টাকা করে কমে যাবে। সর্বোচ্চ কত লাভ করা যায়?

**Thought Process:**
যেহেতু সবার দামই ১ টাকা করে কমছে, আমি চাইব সবচেয়ে দামি পিজ্জাগুলো সবার আগে বিক্রি করতে! কারণ কম দামি পিজ্জার দাম কমে ০ হয়ে গেলেও আমার খুব বেশি লস নেই, কিন্তু ১০০ টাকার পিজ্জার দাম কমে গেলে আমার অনেক লস!
**গ্রিডি স্ট্র্যাটেজি:** বড় থেকে ছোট সর্ট (Descending) করো। তারপর বিক্রি করো।

```cpp
void solve_pizzas() {
    // ... input a[i] ...
    sort(a.rbegin(), a.rend()); // বড় থেকে ছোট

    long long total_profit = 0;
    for (int i = 0; i < n; i++) {
        // i-তম পিজ্জা বিক্রি করার সময় i মিনিট পার হয়ে গেছে
        long long current_price = max(0LL, a[i] - i);
        total_profit += current_price;
    }
    cout << total_profit << "\n";
}
```

### 💊 প্রবলেম ২: Neo's Choice (DIU Summer-25 Prelim A)
**প্রবলেম:** Matrix এ $N$ জন রিক্রুটের পাওয়ার অ্যারে $A$ (ছোট থেকে বড় সাজানো) এবং তাদের স্ট্যাটাস অ্যারে $B$ ($1$ মানে Awakened, $0$ মানে Trapped) দেওয়া আছে। তোমার কাছে ঠিক $K$ টি Red Pill আছে। প্রতিটি পিল দিয়ে স্ট্যাটাস উল্টানো যায় ($0 \to 1$ বা $1 \to 0$)। $K$ টি পিল ব্যবহার করে Awakened রিক্রুটদের মোট পাওয়ার সর্বোচ্চ কত করা যায়?

**Thought Process:**
এটি "K-Negation" প্রবলেমেরই একটু টুইস্টেড ভার্সন!
১. আমাদের টার্গেট হলো যারা Trapped ($0$), তাদেরকে পিল খাইয়ে Awakened ($1$) বানানো, যাতে তাদের পাওয়ার আমাদের টিমে যুক্ত হয়।
২. যেহেতু অ্যারে $A$ ছোট থেকে বড় আকারে সাজানো, সবচেয়ে শক্তিশালী রিক্রুটরা অ্যারের শেষের দিকে আছে।
৩. তাই আমরা অ্যারের **পেছন থেকে (ডানদিক থেকে)** শুরু করব এবং যাদের স্ট্যাটাস $0$, তাদেরকে పিল দিয়ে $1$ বানাব। এভাবে $K$ শেষ হওয়া পর্যন্ত চলতে থাকব।
৪. যদি সব $0$ কে $1$ বানানোর পরও $K$ বেঁচে থাকে (অর্থাৎ আমাদের কাছে অতিরিক্ত পিল থাকে):
   - যদি অবশিষ্ট $K$ **জোড় (Even)** হয়: আমরা যেকোনো একজনকে বারবার পিল খাওয়াব (একবার $0$, আবার $1$), ফলে পাওয়ারের কোনো ক্ষতি হবে না!
   - যদি অবশিষ্ট $K$ **বিজোড় (Odd)** হয়: আমাদের বাধ্য হয়ে এমন একজনকে পিল খাওয়াতে হবে যে আগে থেকেই Awakened ($1$), ফলে সে Trapped ($0$) হয়ে যাবে এবং আমরা তার পাওয়ার হারাব। লস কমানোর জন্য আমরা সবচেয়ে দুর্বল (সবচেয়ে ছোট পাওয়ার যার) রিক্রুটকে পিল খাওয়াব। যেহেতু অ্যারে সাজানো, সবচেয়ে ছোট পাওয়ার হলো $A[0]$!

```cpp
void solve_neo() {
    int n; long long k;
    cin >> n >> k;
    vector<long long> a(n);
    vector<int> b(n);
    
    for (int i = 0; i < n; i++) cin >> a[i];
    for (int i = 0; i < n; i++) cin >> b[i];
    
    // পেছন থেকে শুরু করে 0 গুলোকে 1 বানাই
    for (int i = n - 1; i >= 0 && k > 0; i--) {
        if (b[i] == 0) {
            b[i] = 1;
            k--;
        }
    }
    
    long long total_power = 0;
    for (int i = 0; i < n; i++) {
        if (b[i] == 1) total_power += a[i];
    }
    
    // যদি K বিজোড় থাকে, সবচেয়ে ছোট পাওয়ার (a[0]) বিয়োগ করে দেব!
    if (k % 2 != 0) {
        // a[0] যদি আগে 1 থাকে তবে সেটা 0 হয়ে যাবে, তাই তার পাওয়ার বাদ যাবে
        // (যেহেতু আমরা একটু আগেই 0 গুলোকে 1 বানিয়েছি, এখন সবাই 1, 
        // তাই a[0] এর পাওয়ার total_power এ যোগ করা আছে। একবার বিয়োগ করলেই হবে)
        total_power -= a[0]; 
    }
    
    cout << total_power << "\n";
}
```



### 📅 প্রবলেম ৩: Interval Scheduling (Activity Selection)
**প্রবলেম:** তোমার কাছে $N$ টি অ্যাক্টিভিটি আছে, প্রতিটির শুরুর সময় $S_i$ এবং শেষের সময় $E_i$ দেওয়া। একটি সময়ে তুমি শুধু একটি অ্যাক্টিভিটিই করতে পারো (কোনো ওভারল্যাপ চলবে না)। সর্বোচ্চ কতগুলো অ্যাক্টিভিটি করতে পারবে?

**Thought Process (কেন Greedy কাজ করে?):**
১. প্রথম চিন্তা: "সবচেয়ে ছোট অ্যাক্টিভিটি আগে নাও" — ভুল! একটা ছোট অ্যাক্টিভিটি মাঝখানে থাকলে দুই পাশের বড়গুলো নষ্ট হতে পারে।
২. **সঠিক গ্রিডি:** যে অ্যাক্টিভিটি সবচেয়ে **আগে শেষ হচ্ছে**, সেটা আগে নাও! কেন? কারণ যত তাড়াতাড়ি শেষ হবে, তত বেশি সময় বাকি থাকবে পরের অ্যাক্টিভিটির জন্য।
৩. **ধাপ:**
   - সব অ্যাক্টিভিটিকে **শেষের সময় (End Time)** অনুসারে সর্ট করো।
   - প্রথমটা নিয়ে নাও। এরপর প্রতিটি পরবর্তী অ্যাক্টিভিটির শুরু $\ge$ শেষ নেওয়া অ্যাক্টিভিটির শেষ হলে নাও।

```cpp
int max_activities(vector<pair<int,int>>& acts) {
    // {end, start} বানিয়ে সর্ট করলে end অনুসারে সাজায়
    sort(acts.begin(), acts.end(), [](auto& a, auto& b) {
        return a.second < b.second; // end time ছোট আগে
    });
    
    int count = 1;
    int last_end = acts[0].second;
    
    for (int i = 1; i < acts.size(); i++) {
        if (acts[i].first >= last_end) { // start >= last_end
            count++;
            last_end = acts[i].second;
        }
    }
    return count;
}
```

> **প্যাটার্ন চিনবে:** "ইন্টারভাল/টাস্ক/মিটিং ম্যাক্সিমাম কতগুলো করা যায়" — সবসময় **end time অনুসারে সর্ট**। এটি Interval-related গ্রিডির ভিত্তি।
